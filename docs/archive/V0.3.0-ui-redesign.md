# ExcelSearch V0.3.0 — UI/外观美化方案（准备阶段）

> 状态：**准备阶段**。正式构建时将开启程序内部 UI 辅助目检美化。本文档为调研结论与实施路线，供正式构建时执行。

## 一、现状问题（源码核实）

### 1.1 毛玻璃 bug（必须修复）
- `main.cpp` `ApplyAcrylicEffect()`：用未公开 API `SetWindowCompositionAttribute` + `ACCENT_ENABLE_ACRYLICBLURBEHIND`
- `GradientColor = (alpha << 24) | 0x000000` —— 纯黑渐变层叠加在窗口上，**无文字对比度适配**
- 结果：毛玻璃强度调高后，背景变黑/模糊，STATIC/EDIT 等控件文字仍为黑色 → **看不见文字**
- 仅 Win10 支持，Win11 效果不一致；最大化动画期间效果丢失

### 1.2 UI 堆砌、无美感
- 主界面（`InitControls`）：CreateWindowEx 逐个创建原生 BUTTON/EDIT/ListView，按钮一排平铺，无分组、无层次、无图标、无间距设计
- 管理面板（`AdminPanelWndProc`）：**9 个按钮垂直堆砌**（从 y=50 每 45px 一个），只有文字按钮，无卡片/分组/图标，完全不具备美感
- 子页（SubPage*）同样为原生控件平铺

### 1.3 深色模式不完整
- `ApplyDarkMode()` 仅设置：标题栏 DWM 深色 + ListView 背景/文字/文字背景三色
- STATIC/EDIT/BUTTON/状态栏/滚动条等控件深色适配不足，深色模式下部分区域仍为白色

### 6.2 Win32Acrylic 集成要点（已验证）
- **纯 header**：`#include "Win32Acrylic.h"` 即可；内部用 WRL + C++/WinRT（`winrt\Windows.UI.Composition.*`）+ DirectComposition + D3D11/D2D
- **MSVC 兼容**：库源码用了 `and`/`or` 替代运算符，需先 `#include <ciso646>`（或编译选项启用）
- **链接库**：`d2d1 d3d11 dcomp dxgi windowscodecs windowsapp shlwapi dxguid`（项目 CMake 已有 windowsapp）
- **构造方式**：`Win32Acrylic(HWND)` 构造即创建 DispatcherQueue + Compositor + DesktopWindowTarget + Acrylic Brush，需持有一个实例（成员变量/堆对象）；系统不支持时抛 HRESULT，需 try/catch 兜底
- **可调参数**：`CreateAcrylicBrush(tintColor, luminosityColor)`（默认 `{0.125,0.125,0.125,0.4}` 深色 tint）、`SetBlurAmount(30)`、`SetSaturation(1.25)`；Legacy 配方 `CreateAcrylicBrush_Legacy` 供 Win10
- **替代方案**：Win11 可直接 `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` 用 Mica/Acrylic，更轻量；Win10 用 Legacy 配方
- **✅ 已验证**：编译链接通过；实际创建窗口应用 Acrylic 2 秒运行无崩溃（exit 0。注：验证环境为 Win10（build 19045），走 legacy 配方；此前"Win11"记录为误记，2026-09-02 更正）

### 6.3 darkmode32plus 集成要点（已确认）

   - **去 Win32Acrylic（DirectComposition）**，毛玻璃改用 **Win10 原生 `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)`**（GitHub 主流毛玻璃库 Maplespe/ExplorerBlurMica、sylveon/windows-swca 本质都封装此 API；项目直接用原生实现，零依赖）。原因：Win32Acrylic 的 DComp 与 DWM 无边框渲染(DwmExtendFrameIntoClientArea)冲突会破坏布局（面板/表头/文字错乱，实测）。
   - **无边框 = `WS_THICKFRAME`（保留缩放）+ `WM_NCCALCSIZE=0` + `DWMNCRP_DISABLED`（去 WS_THICKFRAME 深灰焦点边框）**。实测：四周无灰框（聚焦/失焦均无）、窗口四边无透明缝、可缩放、毛玻璃（窗口背景 blur，控件覆盖部分由面板/列表显示、间隙/边缘显示毛玻璃）、UI 正常、功能回归通过。
   - **`DwmExtendFrameIntoClientArea` 不可用**（纯 GDI 项目会破坏布局，实测）。

### 7.4 技术要点/陷阱（避免重复踩坑）
- **验证环境：Win10 22H2（build 19045），不是 Win11**（此前文档"Win11"系误记，2026-09-02 实测更正）。影响：`DWMWA_WINDOW_CORNER_PREFERENCE` 属性在该环境无效（返回 E_INVALIDARG），圆角走 `SetWindowRgn` 兜底；Acrylic 走 legacy 配方。DWM 原生圆角/标准 Acrylic 配方需 Win11 真机验证
- **无边框自绘标题栏（方案B）实现要点/陷阱**：
  - 样式：`WS_POPUP | WS_THICKFRAME | WS_SYSMENU | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_CLIPCHILDREN`；窗口类样式加 `CS_DROPSHADOW` 阴影。`WS_POPUP` 去系统标题栏，`WS_THICKFRAME` 保留系统缩放能力，Min/Max/SYSMENU 保留任务栏图标/系统菜单/最大化行为
  - `WM_NCCALCSIZE` 返回 0：客户区=整个窗口（无边框占位）；`WM_GETMINMAXINFO` 必须用 `MonitorFromWindow`+`GetMonitorInfo`(rcWork) 限制最大化/最大跟踪到工作区（`WS_POPUP` 无系统自动约束，漏了会盖住任务栏）
  - `WM_NCHITTEST` 的 lParam 是**屏幕坐标**，需 `ScreenToClient` 转换再判断；边缘返回 `HTLEFT/HTRIGHT/HTTOP/HTBOTTOM/HTTOPLEFT/TOPRIGHT/BOTTOMLEFT/BOTTOMRIGHT`（6px 热区），标题栏（y<TITLEBAR_H=32）内：按钮区返回 `HTCLIENT`（自绘处理）、其余返回 `HTCAPTION`（系统处理拖动+双击最大化）
  - **无边框窗口样式（最终版）**：`WS_POPUP | WS_THICKFRAME | WS_SYSMENU | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_CLIPCHILDREN`。**必须保留 `WS_THICKFRAME`**——去掉它会失去鼠标拖动边缘缩放（实测确认：WM_NCHITTEST 返回 HT* 需配合 WS_THICKFRAME 才触发系统缩放）。WS_THICKFRAME 会带来 DWM 深灰"焦点边框"（获得焦点/失焦切换后四周一圈灰框 + 底部几像素空隙），**用 `DwmSetWindowAttribute(DWMWA_NCRENDERING_POLICY, DWMNCRP_DISABLED)` 禁用非客户区渲染隐藏**（只影响 DWM 边框，不影响客户区 UI，实测四周无灰框、UI 正常、可缩放）。**毛玻璃（去 Win32Acrylic/DComp）改用 Win10 原生 `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)`**（零依赖，GitHub 主流毛玻璃库同 API；Win32Acrylic 的 DComp 与 DwmExtendFrameIntoClientArea 冲突破坏布局，不可用）。WM_PAINT 在毛玻璃开启时不填不透明背景（让 blur 透出，间隙/边缘显示毛玻璃），无毛玻璃时填白兜底；修复原纯黑 GradientColor bug：tint 用半透明（浅 0x8C 白/深 0x9E 深灰，深浅色联动）。
  - **不要**用 `DwmExtendFrameIntoClientArea(hwnd,&(MARGINS){-1,-1,-1,-1})` 隐藏边框——实测会**把面板容器/表头/文字布局全部打乱**（重影错位、圆角面板背景消失），不可用。旧 SDK 需补宏 `#ifndef DWMWA_NCRENDERING_POLICY #define 2`、`#ifndef DWMNCRP_DISABLED #define 1`
  - **标题栏按钮点击必须 `PostMessage(WM_SYSCOMMAND, SC_MINIMIZE/SC_MAXIMIZE(或 SC_RESTORE)/SC_CLOSE)`，不能 `SendMessage`**：在窗口自身 `WM_LBUTTONUP` 里 `SendMessage` 嵌套派发 SC_MAXIMIZE 时窗口仍持有鼠标捕获（DOWN 里 `SetCapture`），命令被吞不生效；`PostMessage` 投递到消息队列异步处理才生效（本轮实测定位的关键坑，按钮按下态正常但 SC 不执行）
  - **【重要】不要在父窗口 WM_MOUSEMOVE 里对子控件（自绘按钮/编辑框）手动 `InvalidateRect`**：本方案初版为做扁平按钮 hover 高亮，在 WM_MOUSEMOVE 用 `ChildWindowFromPoint`+`InvalidateRect(控件, TRUE/FALSE)` 跟踪，导致**鼠标扫过窗口时输入框和所有按钮被清空消失**（InvalidateRect 触发子控件重绘时内容被清掉，且主窗口 WS_CLIPCHILDREN+WM_PAINT 组合放大问题）。根除：扁平按钮的 hover 高亮由系统 `ODS_HOTLIGHT` 提供（DrawFlatButton 已检查 `itemState & ODS_HOTLIGHT`），**移除手动 InvalidateRect 子控件**；WM_MOUSEMOVE 只做**标题栏**悬停重绘（InvalidateRect 标题栏矩形，局限在 y=0..32，不影响下方子控件）。同时把主窗口 `WM_ERASEBKGND` 返回 1（不擦除，避免擦掉子控件区域）、`WM_PAINT` 统一画整窗背景+标题栏（`WS_CLIPCHILDREN` 使主窗口 DC 自动排除子控件区域，子控件不被覆盖）
  - `CreateRoundRectRgn(x1,y1,x2,y2,nw,nh)` 的 nw/nh 是角椭圆**直径**：视觉 8px 圆角 → 传 16（原实现传 8 实际只有 4px）；`SetWindowRgn` 区域**不随缩放自动更新**，须在 `WM_WINDOWPOSCHANGED`(`!(SWP_NOSIZE)` 时)重建，最大化/最小化取消（`SetWindowRgn(hwnd,nullptr)`）
  - 测试按钮坐标**从右到左**：close=cw-23, max=cw-69, min=cw-115（46px 宽右对齐）；`WM_NCHITTEST` 可用 `SendMessage` 同特权进程回读验证（热区/标题栏/按钮返回值）
  - 跨进程 GUI 自动化：同特权下 `SendMessage` 可送达（本轮实测 WM_NCHITTEST/WM_LBUTTONDOWN 均返回正确值，未受 UIPI 拦截）；真实点击需 `SetForegroundWindow`+`SetCursorPos`+`mouse_event`；截图用 **PrintWindow(hdc, PW_RENDERFULLCONTENT=2)** 或 `CopyFromScreen` 实拍最可靠
- **PowerShell 5.1 脚本编码坑**：ps1 必须纯 ASCII 或 UTF-8 带 BOM；无 BOM 的 UTF-8 中文注释按 GBK 解析会乱码并破坏 here-string 解析（本轮已踩）。另外 `$Pid` 是只读自动变量，脚本参数勿用
- `main.cpp` 是 UTF-8 无 BOM；`app.rc` **必须 UTF-8 BOM**（编辑丢失 BOM 编译报 RC2133）
- 修改含中文的 C++：优先用 edit 工具；批量脚本必须显式 UTF-8 读写，**严禁 Get-Content 默认编码**（会双重编码乱码，需 GBK 逆操作恢复）
- 跨进程 GUI 自动化受 UIPI 拦截不可靠；截图用 **PrintWindow(hdc, PW_RENDERFULLCONTENT=2)** 最可靠
- `LVM_SETITEMSPACING` 曾致 0xC000041D 崩溃，已移除
- 状态栏：`SB_SETTEXTCOLOR=0x0404`/`SB_SETBKCOLOR=0x0405`；`0x0401` 是 `SB_SETTEXT` 会崩溃
- 测试数据：本地 data 目录当前为空；要用真实数据测需设 ShareMode=1 或复制文件到 data
