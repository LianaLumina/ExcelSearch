## A. 部署（`tools\deploy.ps1`）

**实测教训（脚本注释里保留）**：MSYS2 的 `windeployqt` **不复制 MinGW 运行时、也不解析 Qt 传递依赖**——
只跑它会把程序做成"一启动就 0xC0000135"。故脚本增加**依赖闭包补齐**。

| 检查项 | 结果 |
|---|---|
| windeployqt | 产出 `platforms\qwindows.dll` |
| 依赖闭包补齐 | 补齐 **23 个** DLL（5 轮收敛）：MinGW 运行时 3 个 + Qt 传递依赖 20 个 |
| 递归依赖校验 | **依赖完备**（除 Windows 系统 DLL 外无缺失） |
| **PATH 剥离启动测试** | **通过**（把 `C:\msys64\mingw64\bin` 从 PATH 摘掉仍能启动并产出结果） |
| 平台插件 | `qwindows` + **`qoffscreen`** + `qminimal` |
| 开源许可 | Qt LGPL/GPL 全文 + **16 个 msys2 依赖包**许可 + 自带库声明 + 项目 LICENSE |

> ⚠️ 踩坑记录：`windeployqt` 只带 `qwindows`。若不带 `qoffscreen`，部署版跑无头自检钩子会弹
> **"no Qt platform plugin could be initialized"** 致命框并卡住（实测踩到）。脚本已补该插件，
> 并给启动测试加了 **30 秒超时保护**，避免脚本挂死。

| 卸载前结束运行中的程序 | `InitializeUninstall` 先 `taskkill /F /IM excel_search.exe` + 等 600ms | ✅ 复现验证：装 → 启动程序 → 卸载 ⇒ 程序被结束、**目录彻底删除、零残留** |

> 踩坑记录 1：`SetupSetting("AppId")` 返回的是**未反转义**的 `{{GUID}`，直接拼注册表路径会写到
> 自造键 `{{GUID}_is1` 上（真实键是 `{GUID}_is1`）；已在代码里做反转义，并清理了测试期产生的自造键。

> 实测残留的正是「被进程占用」的那批文件：`excel_search.exe` + 全部 `Qt6*.dll` + 其依赖 DLL +

> ⚠️ 踩坑记录 3（**用户实测发现，卸载器"点下一步就异常退出"**）：Pascal 里 `else` 只吃**一条**语句 ——
> 写成 `else WizConfirmed := True; WizForm.Close;` 时，`WizForm.Close` 落在 if 之外**无条件执行**，

> 已补回并双钩子挂载。
>
> ⚠️ 踩坑记录 5（测试方法）：**Inno 自绘控件不响应 `BM_CLICK`**（`TNewButton` 不是标准 Win32 按钮类），
> 用 `SendMessage(BM_CLICK)` "点击"完全无效；必须用**真实鼠标事件**（`SetCursorPos` + `mouse_event`），
> 且点击前要 `SetForegroundWindow`（否则点到压在上面的其它窗口）。

证据（`--report` 一行，可复现）：

```text

normal=880x566|max=1920x1040|avail=1920x1040|maxEqAvail=yes|restore=880x566|

```

读法：`listhbar=off|nav=none`＝目录栏无横向条且**没有任何标题被省略号截断**；
`toplevel,btn=max`＝独立顶层窗口且只有最大化按钮；`frameless=yes,frameDelta=0x0`＝无原生标题栏
（窗口边框与客户区完全重合）；`max=avail`＝最大化正好铺满可用区域、`restore=880x566`＝还原回原尺寸；
`gate0`＝未读完时复选不可勾选、关不掉，`nag`＝此时点确认弹出调侃文案，
`gateRead`＝读到底后复选可用且可关闭，`closedAfterRead=1`＝此时点确认**真的把窗口关掉了**；
`rects`＝控件在窗口内的相对位置（给自动化点击用）。
`--shot --page manual` 生成的截图（浅色/深色）见 `docs/images/说明书窗口-*.png`。

**踩坑记录 7：只截窗口内容的截图骗过了我。**
改完用 `--shot` 看截图一切正常，但用 Win32 `GetWindowRect` 一量：屏幕上的窗口是 **896x605**，
而设计尺寸是 880x566——差的 16x39 正是**原生标题栏与边框**。原因是 `setWindowFlags(Qt::Window)`
漏了 `Qt::FramelessWindowHint`，系统于是额外画了一条标准标题栏；而 `grab()` 只截客户区，截图里看不见。
同样因此，按"窗口内相对坐标"点击会整体下移约 39px 而点空（第一次端到端点击就是这么点空的）。
修复后 `frameDelta=0x0`、屏幕尺寸 880x566 与设计一致。
**教训：验证窗口形态别只看客户区截图，一定要量 `GetWindowRect` / `frameGeometry`。**
