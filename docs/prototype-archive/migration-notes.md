# 回迁标注（qt_ui_proto → excel_search）

本文件列出 Qt 原型相对 **V0.3.0（Win32 主程序）** 的**有意偏离**。回迁时逐条核对，
**不要把这些改回原版行为**，也不要漏搬配套机制，否则会出现"功能看起来对、行为却变了"的问题。

代码中对应的位置标有 `★回迁注意` 注释，可用 `grep -n "★回迁注意" main.cpp` 全部定位。

---

## 1. 二级筛选的基准：【重点】行为变更

| | 原版 V0.3.0 | 本原型 |
|---|---|---|
| 做法 | `DoFilter` 直接对 `g_results` 就地 `filterResults` 并覆盖 | 保存一级结果快照 `m_baseResults`，**每次从基准逐级重算** |
| 后果 | 改了筛选条件会在**上一次结果里继续缩**（越缩越小，无法回到基准） | 标准模式：改条件＝换条件；逐级模式：显式追加条件 |
| 开关 | 无 | `config.ini` 的 `[filter] mode` = `standard`(默认) / `chain` |

- 实现：`m_filterChain`（条件链）+ `applyFilterChain()`；两种模式共用，只是"按下筛选"时**替换**还是**追加**。
- **回迁决策点**：默认是 `standard`（最不易踩坑），但**老用户升级后会觉得行为变了**。
  若要老用户无感，首次迁移应默认置 `chain`；无论选哪个，都要在说明书里写明。
- 附带修正：`清除筛选` 不再重跑一级搜索、也不再重复记历史。

## 2. 标记筛选态也过屏蔽过滤

- 原版：`DoSearch` 的「已标记」分支**不调用** `FilterBlocked` → 被屏蔽的条目仍出现在「已标记颜色」视图里。
- 本原型：该分支也过 `filterBlocked`（更一致）。已实测**不丢数据、完全可逆**（解除屏蔽后立刻回到标记视图）。
- **回迁注意**：保留此修正时，`标记清除` 页的计数仍是**全部标记**（含被屏蔽），文案需说明，否则会被当成 bug。

## 3. 屏蔽 / 标记的身份键与磁盘文件名一致

- 原版曾用 .xse **负载内的明文名**做键，导致与 `setFileMeta`/缓存头 key 不一致（V0.3.0 已修）。
- 本原型统一用**磁盘文件名** `(文件名, 工作表, 行号)`。回迁时勿退回明文名。

## 4. 缓存命中判定：全量清单精确匹配

- 原版：`namesMatch` 只比较缓存头里的 `loadedFiles` 与磁盘文件；**存在被跳过的 .xse 时会永远不命中**。
- 本原型：新增 `cache.inv`（`EXIV1`）记录**全量清单**（含被跳过文件），逐项精确相等 + 10 天 TTL 才命中。
- **回迁注意**：必须把 `cache.inv` 机制一并搬过去（含 `collectDiskFiles` / `writeInventory` / `readInventory`），
  只搬 `cache.dat` 会退化成"有 skip 文件就永不命中"。

## 5. 智能列：默认布局与列名解析

- 原版：结果列表**固定 7 列**（序号/文件名/工作表/行号/匹配内容/核定工日/工时代码）。
- 本原型：列数与列内容**可配置**（3–7 列；序号/文件名/匹配内容固定），默认 5 列（工作表/行号），
  因为原版那两个硬编码列名在部分数据里并不存在（会显示空列）。
- 列名解析：`resolveColumnSource()` —— 内建元数据 → 表头"包含" → `rapidfuzz ratio ≥ 60` 兜底；
  **校验与取列共用同一个函数**（原版 `BuildColMap` 只做"表头包含"，两者若分开会出现"校验通过但列取不到值"）。
- **回迁注意**：默认列由 `config.ini` 的 `[smartcols] list` 决定；`核定工日`/`工时代码` 不再硬编码。

## 6. 高级设置的门禁入口

- 原版：搜索框输魔法词 `<隐藏入口关键词>` + 弹窗密码；超管 `<超管密码>`。
- 本原型：设置页内的同级分区「高级设置」，选中时显示**盖住内容的解锁层**（非弹窗），**离开即上锁**；
  不再有隐藏入口；超管 `<超管密码>` 仍硬编码不可改。
- **回迁注意**：入口形式变了，说明书与用户习惯需同步更新。

## 7. 标记的视觉呈现

- 原版：整行**文字变色**（5 色）。
- 本原型：**行首色条**（`MarkBarDelegate`，只补画首列左缘），背景/斑马纹/选中高亮仍走默认绘制。
- 纯视觉差异，但用户可感知；色索引顺序与原版一致（0红 1紫 2蓝 3绿 4黄）。

## 8. 搜索历史：新增可配置项

- 原版：注册表 `MULTI_SZ`，固定 20 条，无时效。
- 本原型：存储上限仍 20；新增**下拉显示条数（不显示–10）**与**删除时效**
  （10 分钟 / 30 分钟 / 1 小时 / 6 小时 / 12 小时 / 关闭程序后删除·不落盘）。
- **仅一级搜索记历史，二级筛选不记**（原版一致，本原型显式保证）；无头自检模式不记历史。
- **回迁注意**：`hist/items` 用 `时间戳<TAB>关键词`、换行用 QSettings 的 `\n` 转义；
  时效为"关闭程序后删除"时必须**清空落盘内容**。

## 9. 配置后端不同（最容易踩）

- 原版：Windows 注册表 `HKCU\Software\ExcelSearch`。
- 本原型：`%APPDATA%\ui_proto\ExcelSearch\config.ini`（QSettings IniFormat，UTF-8）。
- **回迁注意**：必须先决定配置后端——是沿用注册表、还是整体迁到 ini。
  若迁移到 ini，需要写一次**注册表 → ini 的搬迁**（密码、屏蔽、标记、历史、共享路径、主题等），
  否则老用户会"所有个性化设置丢失"。

## 10. 【预留】「实用工具」标签页：只留接口，暂不实现

- **定位**：顶部标签 = 主流程页（`搜索` / `设置` / 预留 `实用工具`）。
  使用频率明显低于主流程（搜索·筛查·查看·导出·屏蔽·标记）的**辅助功能**，集中放进「实用工具」，
  以保持主界面常驻功能精简。
- **边界（分类规则，务必照搬）**：
  1. 低频、非管理性的辅助工具 → 将来放「实用工具」；
  2. **需要密码的管理类内容仍然只放「设置 → 高级设置」**，不要混进实用工具；
  3. 主流程高频功能不要因为"偶尔用"就塞进实用工具，判断标准是**使用频率**而非实现难度。
- **本原型现状**：`kEnableUtilTab = false`（`main.cpp` 顶部有整段说明注释），
  **不出现该标签**；只保留注册通道：`m_utilTools` + `registerUtilTool()` + `makeUtilPage()`（含空态）。
- **将来启用只需两步**（已实测可行，见下）：
  1. `kEnableUtilTab` 置 `true`；
  2. 每个工具调用一次 `registerUtilTool(标题, 工厂)`。
  `makeUtilPage()` 自动生成"左列表 + 右内容栈"，**不要另写第二套标签注册逻辑**。
- **★回迁注意（防重做出 bug）**：
  - 若回迁时**不搬**这个标签，至少要把上面的**分类规则**写进说明书，
    否则以后又会把低频功能随手塞回主界面或设置页；
  - 若搬，则连 `registerUtilTool` 的注册方式一起搬，**不要并行维护两套注册机制**；
  - `makeUtilPage()` 的空态必须保留：启用后若还没注册任何工具，
    应显示"暂无实用工具"，而不是一片空白（空白容易被误报成 bug）。
- **已验证**：把开关临时置 `true` 编译后，顶部出现「实用工具」标签且空态正常显示；
  置回 `false` 后标签消失、`--tab 2` 为安全空操作，界面与改动前**逐字节一致**。

## 11. 统计报表：**决定不迁移**

- 原版有「统计报表」（`ui_dialogs.cpp` 的 `ShowStatDialog`）：按文件/表输出
  `核定工日合计 / 有效行数 / 总行数`，并可导出 `核定工日统计.csv`。
- **决定**：**本原型不实现，回迁时也删除**。理由（原版实现的四个结构性问题）：
  1. `有效行数` 实为"该列能被解析成数字的行数"，表里没有该列时显示 0/N，**看着像数据坏了**；
  2. 用 `std::stod` 只吃数字前缀，`"3人*3天=9"` → **算成 3**，**静默算错**；
  3. 全表无差别累加，不排除表内小计行/汇总行，可能重复计入；
  4. **完全无视当前筛选与屏蔽**，数字与屏幕上所见无关，事后无法复现口径。
- **回迁注意**：
  - 删除要**走弃用路径**（先隐藏入口保留一版 → 下一版删代码 → 说明书标注"已移除统计报表"），
    **不要一次性硬删**，避免老用户直接撞上"功能消失且无说明"；
  - 删除前建议先做一次**对账验证**：用原版报表算一遍 vs Excel 手算一遍，若对不上，
    则该功能属于"一直在给错数"，删除是修正错误而非砍需求；
  - **若将来"合计"这个需求被证明是真的**，不要复活旧报表，改做成
    **搜索结果上的一行汇总**（跟随筛选/屏蔽实时变化、合计列可选、非数值行显式提示不计入），
    并按第 10 条放进「实用工具」或结果卡片。

## 12. 共享模式：数据源切换 + 不可达兜底 + 30 小时缓存

| | 原版 V0.3.0 | 本原型 |
|---|---|---|
| 开关 | `g_shareMode` + `g_dataFolder = g_sharePath` | `config.ini` 的 `[share] enabled` + `[share] path`，数据源由 `dataSourceDir()` 统一决定 |
| 探测线程 | 在 UI 线程调 `fs::exists`（UNC 不通时会假死） | **探测放 worker**（`ProbeWorker`），UI 只显示"正在连接共享目录…" |
| 不可达兜底 | 强制吃缓存（`cacheTemp`），不清空视图 | 同样吃缓存，且**更严格**：见下 |
| 只读 | 共享模式跳过明文自动删除 | 共享模式不写、不删共享上任何文件 |
| 缓存 TTL | 无区分 | **共享 30 小时**、离线 10 天（`cacheTtlSec()`） |
| 附加能力 | 无 | 「共享设置」内新增 **测试连接** 与 **强制重载**；改完路径自动执行"测试→成功才重载" |

- **不可达旁路（必须照搬，否则会退化成"断网把数据清空"）**：
  共享目录不可达时，`cache.inv` 清单**根本读不到**，按严格清单匹配会判 miss →
  若照常启动 LoadWorker，它会产出一个空索引并**把好缓存覆盖成空**。
  因此设计上：`LoadWorker::unreachable` 置位 → 主线程走 `loadCacheFallback()`：
  ① 跳过清单校验，直接 `loadFromFile(cache.dat)`；
  ② **绝不回写缓存**；③ 状态行标注"共享目录不可达，已使用缓存（N 小时前）"。
- **自动流程（用户定的）**：路径改完（`editingFinished`）→ 规范化 → 保存 →
  **测试连接 → 成功才执行强制重载**；**测试失败则静默拒绝执行强制重载**（不弹窗、不重载，只在状态行显示失败原因）。
- **回迁注意**：
  - 探测必须放后台线程，UNC 的 `exists()` 在主机不可达时可阻塞数秒~数十秒；
  - 失败原因要尽量区分"路径不存在/主机不可达"与"拒绝访问"（权限），否则用户会查错方向；
  - 切换模式 = 换数据源，必须**清空索引并重新加载**，不能只改路径；
  - `m_dataDir` 必须在 `buildUi()` 之前赋值（分区工厂在 buildUi 里就会读它，晚了状态行会显示空路径）。

## 13. 明文自动删除：**决定不迁移**（原版最危险的一处）

- 原版离线模式：若 `xxx.xse` 与 `xxx.xlsx` 同基名共存，且
  ① .xse 头记录的 (mtime,size) 与明文文件一致、② 解密后表数据与明文解析结果相等
  → **`DeleteFileW` 直接删除明文 .xlsx**。
- **问题**：`DeleteFileW` 是**硬删除、不进回收站、且无任何用户确认**；判断链条任一环节偏差
  就是**静默、不可逆的数据丢失**。原版作者自己也在共享模式把它关掉了。
- **决定**：**不迁移**。原型不实现该行为，回迁时也不要照搬。
- **若该需求将来被证明为真**，必须改造成三条底线：
  1. 放进「高级设置」作为**显式管理动作**（不是每次加载的副作用）；
  2. **先列出将删清单 + 二次确认**；
  3. **可恢复**：移入回收站（`SHFileOperation`）或 `_已归档明文\` 子目录，**绝不 `DeleteFileW`**。
  并且**共享模式下永不执行**。

## 14. 托盘支持 + 关闭方式选择（本版新增，回迁前已完成）

- 对齐原版 V0.3.0.1 的**「隐藏到托盘」**能力：
  - 托盘**左键单击/双击 = 恢复并置前**；
  - **托盘右键菜单** = `显示主界面` / `退出程序`（只有这里是无条件真退出）；
  - **首次隐藏弹气泡**「已最小化到托盘，双击图标可恢复」（每次启动只弹一次）；
  - 退出时隐藏托盘图标（等价原版 `WM_DESTROY` 里的 `NIM_DELETE`）。
- **⚠️ 关闭行为有意偏离原版（本版改动）**：
  - 原版：点 × **直接**隐藏到托盘（不询问、无法设置）；
  - 本版：点 × **默认弹「关闭方式」对话框**（`最小化到托盘` / `直接关闭`，左下角可勾 **`不再询问`** 记住选择）；
    并新增 **设置 → 通用设置 → 关闭选项设置**（三选一：每次询问 / 直接关闭程序 / 最小化到托盘）便于随时调整。
  - 对应配置键 `ui/closeAction` = `ask`(默认) / `close` / `tray`。
  - 实测：`close`→进程退出；`tray`→进程驻留；`ask`→被对话框拦住（`CloseMainWindow()` 触发验证）。
- 与 `实用工具/待办` 的关系：托盘是 V0.4「管家模式」常驻后台的前置能力。
- **回迁注意**：
  - `closeEvent` 里必须判断"是否真的在退出"，否则会出现**关不掉的窗口**；
  - **无托盘环境必须降级**：`QSystemTrayIcon::isSystemTrayAvailable()` 为假时，× 仍按普通关闭处理
    （否则窗口一隐藏，用户既看不到窗口也找不到图标）；
  - 程序图标按强调色程序化绘制（无资源文件），改强调色时要同步刷新托盘图标与任务栏图标；
  - 对话框里的 Esc = **取消本次关闭**（窗口保持打开），避免用户被"只有两个选项"困住。

## 17. 必须构建为 **GUI 子系统**（否则双击会伴随黑色命令行窗口）

- **现象**：原型一度每次启动都伴随一个**黑色命令提示符窗口**。
- **原因**：`CMakeLists.txt` 用普通 `add_executable(ui_proto ...)` 且**未设 `WIN32_EXECUTABLE`**，
  CMake 链接出的是**控制台子系统**程序 —— 实测 PE 可选头 `Subsystem = 3 (WINDOWS_CUI)`，
  Windows 会为它分配控制台并显示窗口（双击也会）。
- **修复**：`set_target_properties(ui_proto PROPERTIES WIN32_EXECUTABLE TRUE)`
  （MinGW 等价 `-mwindows`，MSVC 等价 `/SUBSYSTEM:WINDOWS`）→ 实测 `Subsystem = 2 (WINDOWS_GUI)`，黑框消失。
- **★回迁注意（重点）**：
  - 原版 `excel_search`（MSVC）**已有** `/SUBSYSTEM:WINDOWS`，本身没有这个问题；
    但**改用 Qt/MinGW 构建后必须重新确认**，否则会把"黑框"这个已修的问题带回正式版；
  - **验证方法**：读 PE 可选头 Subsystem 字段应为 `2`（不是 `3`），或直接双击看有没有黑框；
  - **附带影响**：GUI 子系统**不分配控制台**，因此**任何 `printf` / stdout 调试输出都会失效**。
    原型的自检钩子因此改为 `--out <文件>` 写文件（`--report` 本来就是写文件）。
- **自检钩子输出调整**：`--search` / `--colprobe` 不再打印到 stdout，改为 `--search ... --out <文件>`；
  另外 GUI 子系统下 PowerShell 的 `&` 调用**不会等待**进程结束，脚本里需用
  `Start-Process -Wait`（否则会读到"文件还没写完"的中间态）。

## 18. 运行时唯一性（单实例）——**原版缺失的潜在 bug，回迁必须带上**

- **风险链条（真实，不是理论）**：多个实例共享同一份 `config.ini` 与同一对 `cache.dat` + `cache.inv`。
  缓存是"两个文件配对"的（`cache.inv`=清单，`cache.dat`=数据），写入**非原子**，
  两个实例交错后可能留下**撕裂对**：`inv` 来自 A（共享目录清单）、`dat` 已被 B（本地 data）覆盖。
  此时 A 启动 → 清单恰好匹配 → `loadFromFile` 把 **B 的数据当成共享数据**加载 →
  **缓存显示命中、结果是错的、完全没有报错**。此外还有 `config.ini` 后写覆盖（屏蔽/标记/历史被静默丢弃）。
- **原版状况**：`excel_search` **也没有任何单实例保护**（grep `CreateMutex` / `单实例` / `FindWindow` 均 0 命中），
  且原版同样是 `g_shareMode` + 同一个 `cache.dat` → **同样的风险在原版就存在**。这是原版遗留缺陷，不是原型独有。
- **修复（本原型已实现）**：
  - 用 `QLocalServer`/`QLocalSocket` 占一个命名通道 `ExcelSearchUiProto.V0.3.1.5.single`；
  - 第二个实例：连得上 → **普通启动就把已运行实例的窗口唤到前台然后自己退出**；自检钩子模式则**明确报错退出**
    （写 `error=another-instance-running`），**绝不去和运行中的实例抢缓存/配置**；
  - 连不上 → `QLocalServer::removeServer()` 清残留名 → `listen()` 成为唯一实例。
  - 实测：第二实例 4 秒内退出、进程数恒为 1；实例在跑时钩子明确报错；关掉后钩子恢复正常。
- **回迁注意**：
  1. **必须把这个行为搬过去**，否则原版的"多实例静默错数"会原样保留；
  2. 需要 **Qt6::Network** 模块（`QLocalServer`/`QLocalSocket`）；CMake 里
     `find_package(Qt6 REQUIRED COMPONENTS Widgets Network)` + 链接 `Qt6::Network`；
  3. 若将来产品上要**允许同时开多个实例**（例如"多数据源并排对比"），那**必须补做缓存配对校验**：
     在 `cache.inv` 里记录 `cache.dat` 的大小（或哈希），加载时校验一致才用 ——
     但**在强制单实例的前提下不必做**：单写者场景下，即使崩在两次写之间留下
     "新 dat + 旧 inv"，旧 inv 只会在磁盘未变时匹配，而那时的 dat 也对应同一份数据，因此仍然正确。

## 19. 控件动效（V0.3.1.5 原型内已实现，回迁按本条整段搬运）

**定位**：给已完备的界面加一层**克制、跟手**的控件动效（hover 颜色过渡 / 页面与分区切换 / 可折叠卡片 /
toast 与解锁层淡入），**不改变任何业务行为**，并且**可以一键关闭**。
设计与节拍表见 `docs/动效设计.md`（含时长/easing/令牌/验证矩阵/刻意不做清单）。

### 19.1 关闭动效开关（**必须一起搬**）

| 方式 | 写法 | 语义 |
|---|---|---|
| 环境变量 | `UI_PROTO_NO_ANIM=1` | 在窗口构造**之前**读取；`animMs()` 一律返回 0 → 不装 effect、不起动画，直接落终态 |
| 命令行 | `--no-anim` | 等价 |

- **为什么必须有**：离屏截图/自检若拍到动画中间态，验证就变成随机的；回迁后所有截图回归都依赖这个开关。
- `--report` 新增字段 `anim=on|off`（既有字段含义未变），用来证明开关生效。
- 回迁后若换成别的开关名（如注册表项 / 设置页开关），**必须同步改 `docs/动效设计.md` 与 README 的自检说明**。

### 19.2 与 V0.3.0 原版的差异（有意偏离）

| | 原版 V0.3.0 | 本原型 |
|---|---|---|
| hover 反馈 | QSS/自绘均为**瞬时**换色 | 自绘控件与列表/表格行走**颜色过渡**（120ms Standard 曲线；第二轮又加了圆角微变形与按下反馈，见第 20 条） |
| 页面切换 | 直接切 | 淡入 + 8px 上移（150–170ms） |
| 结果卡片 | 固定高度、不可折叠 | **可折叠**（点标题栏，180ms 高度动画 + 箭头旋转） |
| 列表 hover 底色 | 由 QSS `QListWidget::item:hover` 画 | 改由 `RowDelegate` 自绘（QSS 不支持 transition）；文字色仍走 QSS 瞬时切换 |
| 结果表行 hover | 无 | 整行底色过渡（新能力） |
| 关闭键 hover 色 | 硬编码 `#E5484D`（深浅色同值） | 取 `Proto.closeHover` 令牌（深色 `#C14242`、浅色 `#E5484D`） |
| 折叠状态 | — | **不持久化**（不新增配置键；重启即全部展开） |

- **配置格式零变化**：动效没有新增任何 `config.ini` 键，`[ui] / [search] / [filter] / [crypto] / [share] / [block] / [mark] / [smartcols] / [hist] / [admin]` 各段与动效前逐字节一致。
- **构建配置零变化**：没有新增源文件、依赖或 Qt 模块（仍只有 `Widgets + Network`），`CMakeLists.txt` 未动。

### 19.3 回迁时必须照搬的实现要点（改坏了的典型症状也写在这里）

1. **顶级窗口永远不做几何/淡入动画**：原型开 `WA_TranslucentBackground`，Win10 下动画会闪 ——
   动效只作用在**子控件**上。改坏了 = 窗口闪、拖动时残影。
2. **`StateTint`（第一轮叫 `HoverTint`）的选择器必须与生成的 QSS 一一对应**：`#primaryBtn`/`#tbBtn`/`#navBtn` 用带 id 的选择器，
   而 `#themeBtn` 在 QSS 里没有专属规则（只吃通用 `QPushButton`）→ 它的选择器就用 `QPushButton`。
   改坏了 = hover 过渡"看不见"。
3. **QSS 里绝不写半透明背景做 hover**：透明底按钮的"透明"要用 `backDropOf()`（`panelBg`/`card`）取真实底色，
   做**两个不透明色**之间的插值。写 `rgba(...,0.4)` 时中间帧会被 Qt 合成成深灰（实测 `#BBBBBF`），
   改坏了 = hover 时闪一下深色。
4. **hover 底色只能自绘，不能靠 `QStyleOptionViewItem::backgroundBrush`**：装了 QSS 的 `QTableView` 会接管
   `::item` 绘制，`backgroundBrush` 被丢掉（实测设了也一像素不变）。自绘要放在**基类之前**（这样文字不被染色）。
5. **`QGraphicsOpacityEffect` 用完即摘**：长期挂着会改渲染路径、伤性能；摘的时候要延迟一拍并做 identity 判断
   （在 `finished` 回调里直接删会把它的子动画一起删）。
6. **动画的位移动画**：第一轮用"布局上边距"表达（子控件在布局里不能直接改坐标），基准边距存进控件属性；
   **第二轮已改为 `FadeSlideEffect` 在 effect 内平移**（边距动画每帧重排整棵子树，既费又抖，且只能单向）——
   回迁时以第 20 条的 A5 为准。
7. **勾选态/选中态不参与过渡**：`:checked` 的强调色是状态表达，被 hover 冲掉会让"当前页"看不出来。
8. **折叠只压高度上限，不动布局 stretch 因子**；展开结束要解除上限，否则窗口缩放时卡片长不高。
9. **`QListWidget::item:hover` 那条 QSS 不能留**：留着的话它的瞬时不透明底色会盖住自绘的过渡动画。
   若有列表**没装** `RowDelegate`，那个列表就没有 hover 反馈了 —— 加列表时记得调 `enableRowHoverAnim()`。

### 19.4 回归自检（回迁后照跑）

- `--search 工日` → `hits=54 blocked=7`；`--search 工日 --filter 辅助,检修` → `26 / 28`；

## 20. 控件动效第二轮：现代感 / 灵动感（V0.3.1.5 原型内已实现）

**与第 19 条的关系**：19 条是第一轮（基线与开关：hover 过渡 / 页面切换 / 可折叠卡片 / toast / 一键关闭），
本条约第二轮在**同一套开关与令牌约束**下把"动作质量"提上来。两轮共用同一个 `UI_PROTO_NO_ANIM=1` / `--no-anim` 开关。

### 20.1 本轮新增（回迁要一起搬）

| 代号 | 内容 | 回迁要点 |
|---|---|---|
| A1 | **曲线库**（Enter=`cubic-bezier(.05,.7,.1,1)` / Standard=`(.2,0,0,1)` / Exit=`(.3,0,.8,.15)` / Spring=二阶阻尼 ζ=.7 ω=16）+ 时长三档 + 错峰常量 | 曲线与时长**只允许从这一处取**；颜色过渡一律不用 Spring（颜色过冲会被看成闪） |
| A2 | **数值滚动**（统计数字滚到目标值，OutExpo 420ms，0/40/80ms 错峰） | **必须精确落定**（结束时 setText 目标值）；滚动期按目标文本预留最小宽度、结束复位，否则数字变长会顶动布局 |
| A3/A4/A6 | **StateTint**：hover 底色 + **圆角微变形** + **按下** + **输入框焦点边框**过渡 | 圆角只改绘制不触发 relayout；勾选态不参与过渡；`#themeBtn` 的选择器用通用 `QPushButton`；颜色全程不透明（`backDropOf`） |
| A5 | **FadeSlideEffect**（位移+淡入都在 effect 内）+ **方向感知切页** | **取代第一轮的"动画布局边距"**：边距动画会每帧重排整棵子树（页面挂着结果表），既费又抖。窗口本体依旧不动 |
| A7 | **父子错峰**（容器先到、内容随后 40ms） | `cardFrame` 用 `animChild` 属性登记"随后到"的内容控件 |
| B1 | **结果表入场错峰**（首屏 8 行 / 20ms） | 用**单动画 + 每行相位公式**（`f(动画值, 行号)`），不要给每行起定时器、不要用墙上时钟 |
| B2 | **折叠父子编排** + 箭头 Spring 回弹 | 容器 Enter / 箭头 Spring / 内容 Standard 相位；effect 用完即摘 |
| B3 | **列表选中态交接**（旧选中滑走淡出 140ms） | 只用于列表（表格选中是整行强调色，不需要） |
| B4 | **加载不确定进度细条**（`LoadBar`） | **叠加层、不进布局**（进布局会让整页在加载时上下跳）；关闭动效时完全不出现 |
| B5 | 锁图标错峰 + **密码错误横向阻尼抖动**（`shakeAnim`） | 抖动在 effect 内平移，**不碰布局** |

### 20.2 本轮踩过并修掉的坑（回迁时不要重新踩）

1. **QSS 半透明背景做 hover 会"闪"**：中间帧被 Qt 合成到不受控的中介底色上（实测偏成深灰 `#BBBBBF`）。
   → 透明底按钮的"透明"必须用 `backDropOf()`（`panelBg`/`card`）取真实底色，做**两个不透明色**之间的插值。
2. **装了 QSS 的 `QTableView` 会丢掉 `QStyleOptionViewItem::backgroundBrush`**（`QStyleSheetStyle` 自己接管 `::item` 绘制）
   → hover / 入场错峰的底色**必须自绘**，而且画在基类**之前**（文字才不被染色）。
3. **`settleAnim` 的默认等待必须覆盖最长的动效链**：本轮加了 420ms 的数值滚动后，旧的 420ms 等待把
   `entries=43846` 拍成了 `43844`。→ 统一用 `kSettleMs`，加更长的动效就要同步调大。
4. **焦点输入框的文字光标会让逐像素对比随机差 14px** → 截图路径统一 `setCursorFlashTime(0)`。
5. **统计数字的处理：加载期间保持旧值 + 只有变大才滚动**
   - 加载开头会 `m_engine.clear()`；原版在这里还顺手 `updateStats()` 把三个数字写成 0（旧版瞬时置 0 看不出来），
     一旦把这次**下降**做成滚动动画，用户就会看到"索引记录从 43846 一路滚到 0"，像是数据在被删；
   - 修法两条：① `loadData()` 开头**不再刷新**统计数字（加载期间保持上一次的值——"加载中"显示 0 没有信息量，
     还会误导），等新数据到位再由收尾路径统一刷新；② `setStat()` **只在变大时滚动**，相等/变小直接落值。
   - 数字终值必须精确（动画只是在途，不是结果）。
6. **进度反馈不能只挂在"起了后台线程"的分支上**：缓存命中时 `loadData()` 会直接 return（本机 `cache=hit`，
   加载只要几毫秒）→ 细条永远不出现，等于没做。→ 任何一次加载/重新加载都点亮细条，并给一个

## 21. 性能修复：模糊补充去重从 O(n×m) 改为 O(n+m)（**行为微调**）

- **背景**：回迁前的性能冒烟（`docs/性能与健壮性冒烟报告.md`）在 52.5 万条索引 / 10 万命中下实测：
  搜索「张三」**关闭模糊 2,312 ms、开启模糊 75,648 ms** —— 单次搜索 **75 秒**，用户会以为程序卡死。
- **根因**：模糊补充的去重写成了 `for (fuzzy) for (exact)` 双重循环，复杂度 **O(n×m)**；
  10 万 × 10 万 ≈ **1e10 次比较**。**原版没有这个问题**（原版只在精确搜索无结果时才走模糊，
  且没有"补充并去重"这一步）。
- **修复（本原型特有，回迁时一并搬）**：
  1. 精确结果先入 `std::set<tuple<文件名,工作表,行号>>`，模糊补充用 `.insert().second` 做 **O(1) 查重**（整体 O(n+m)）；
  2. **精确命中 ≥ `kFuzzySupplementMaxExact`（5000）条时跳过模糊补充** —— 结果集已有几千条，
     再补近义词对用户没有意义，还白扫一遍全索引。
- **★行为微调（有意偏离原版）**：第 2 条使"精确命中很多时不再出现 `（含模糊补充）` 字样与补充行"。
  实测 75,648 ms → **2,423 ms（31×）**；小结果集（146 条）下模糊补充仍正常工作。
- **兼容性**：`--report` 字段未变；`m_lastExact/m_lastFuzzy` 语义未变（仍分别统计精确与补充条数）。
